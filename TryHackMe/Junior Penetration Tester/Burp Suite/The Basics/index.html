Was ist Burp Suite?

Burp Suite ist ein Java-basiertes Framework, das speziell für das Penetration Testing von Webanwendungen entwickelt wurde. Es agiert als Man-in-the-Middle-Proxy — es fängt den gesamten HTTP/HTTPS-Traffic zwischen Browser und Zielserver ab und ermöglicht es, Requests und Responses in Echtzeit zu inspizieren, zu modifizieren oder an andere Tools weiterzuleiten.

Der Industriestandard ist so weit verbreitet, dass Grundkenntnisse in Burp Suite für jeden Web-Application-Pentester als essenziell gelten.

Edition Merkmale Preis

Enterprise Enterprise Server-basiert, kontinuierliches automatisiertes Scanning, CI/CD-Integration, periodische Schwachstellen-Prüfungen. ab ~6995 $/Jahr

Features of Burp Community

Obwohl die Community Edition eingeschränkt ist, bietet sie eine solide Grundausstattung an manuellen Werkzeugen. Hier eine Übersicht der verfügbaren Module:

Tool Funktion
Proxy Abfangen und Modifizieren von HTTP/HTTPS-Requests und -Responses zwischen Browser und Server.
Repeater Erfasste Requests manuell bearbeiten und beliebig oft erneut senden — ideal für iteratives Testen.
Intruder Automatisiertes Fuzzing und Brute-Force-Angriffe auf Endpoints. In der Community Edition rate-limited.
Decoder Daten kodieren/dekodieren (Base64, URL-Encoding, Hex, etc.) und Hashes berechnen.
Comparer Zwei Datensätze auf Wort- oder Byte-Ebene vergleichen — nützlich zum Erkennen feiner Unterschiede in Responses.
Sequencer Entropie-Analyse von Tokens und Cookies, um die Zufälligkeit und damit die Sicherheit zu bewerten.
Logger Protokollierung des gesamten Netzwerk-Traffics für spätere Analyse.
Extender (BApp Store) Erweiterungen laden — in Java, Python (via Jython) oder Ruby (via JRuby) geschrieben. Zugang zum BApp Store für Drittanbieter-Plugins.

Installation

Burp Suite Community Edition ist auf Kali Linux und der TryHackMe AttackBox bereits vorinstalliert. Für andere Systeme kann Burp Suite von der PortSwigger-Website heruntergeladen werden.

Installationsschritte (Linux)

  1. Installer von der offiziellen PortSwigger-Seite herunterladen (Verfügbar für Windows, macOS, Linux).
  2. Installer ausführen: Mit sudo für systemweite Installation, ohne sudo wird in ~/BurpSuiteCommunity/ installiert.
  3. Standard-Einstellungen während der Installation akzeptieren.
  4. Burp Suite starten und beim Start "Temporary project" wählen (Community Edition unterstützt kein Speichern von Projekten).
Hinweis

Burp Suite benötigt eine Java Runtime Environment. Der offizielle Installer bringt eine gebundelte JRE mit, sodass keine separate Java-Installation nötig ist.

If you have chosen not to use the AttackBox, ensure that you have a copy of Burp Suite installed before proceeding.

The Dashboard

Das Dashboard ist die Startoberfläche von Burp Suite und gliedert sich in vier Quadranten, die einen schnellen Überblick über den aktuellen Zustand liefern:

1. Tasks

Definiert Hintergrund-Aufgaben. In der Community Edition steht standardmäßig der "Live Passive Crawl" zur Verfügung, der besuchte Seiten automatisch in die Site Map aufnimmt.

2. Event Log

Protokolliert alle Aktionen: Proxy-Start, Verbindungsdetails, durchgeführte Operationen. Wichtig für Debugging und Nachvollziehbarkeit.

3. Issue Activity

Nur Professional Edition — zeigt vom automatischen Scanner identifizierte Schwachstellen an. In der Community Edition leer.

4. Advisory

Details zu gefundenen Schwachstellen: Beschreibung, externe Referenzen, Remediation-Empfehlungen. Reports können exportiert werden.

Tipp

Die Fragezeichen-Icons (?) neben vielen UI-Elementen bieten kontextsensitive Hilfe direkt innerhalb der Anwendung.

Options / Settings

Burp Suite unterscheidet zwischen zwei Einstellungsebenen:

  • Global (User) Settings: Gelten für die gesamte Burp-Installation und werden persistent gespeichert.
  • Project Settings: Gelten nur für die aktuelle Session. In der Community Edition können Projekte nicht gespeichert werden — alle Project Settings gehen beim Schließen verloren.

Das Settings-Menü bietet eine Suchfunktion, einen Type-Filter (User/Project) und eine übersichtliche Kategorisierung aller Optionen.

Introduction to the Burp Proxy

Der Proxy ist das Herzstück von Burp Suite. Er fungiert als Man-in-the-Middle zwischen Browser und Zielserver und ermöglicht das Abfangen, Inspizieren und Manipulieren des gesamten HTTP/HTTPS-Traffics.

Kernfunktionen

  • Interception: Requests werden festgehalten, bevor sie den Server erreichen. Per Button Intercept is on/off steuerbar.
  • Forwarding/Dropping: Abgefangene Requests können weitergeleitet, verworfen oder an andere Burp-Tools gesendet werden.
  • Logging: Auch bei deaktivierter Interception wird der gesamte Traffic automatisch protokolliert.
  • WebSocket-Support: Bidirektionale WebSocket-Kommunikation wird ebenfalls erfasst.

Wichtige Proxy-Einstellungen

  • Response Interception: Regelbasiertes Abfangen von Server-Responses (standardmäßig deaktiviert).
  • Match and Replace: Regex-basierte automatische Modifikation von Requests/Responses — z.B. User-Agent ändern, Cookies manipulieren.

Sub-Tabs

  • HTTP history: Chronologische Liste aller HTTP-Requests/Responses.
  • WebSockets history: Analog für WebSocket-Kommunikation.

09

Connecting through the Proxy — FoxyProxy

Um den Browser-Traffic durch Burp Suite zu leiten, wird das Browser-Addon FoxyProxy verwendet. Es ermöglicht das schnelle Umschalten zwischen direkter Verbindung und Proxy.

Einrichtung Schritt für Schritt

  1. FoxyProxy Basic als Browser-Erweiterung installieren (auf der AttackBox bereits vorinstalliert).
  2. FoxyProxy-Icon klicken → Options öffnen.
  3. Auf "Add" klicken, um eine neue Proxy-Konfiguration anzulegen.
  4. Konfiguration eingeben: 
    Title:    Burp
Proxy IP: 127.0.0.1
Port:     8080
  5. Konfiguration speichern.
  6. Über das FoxyProxy-Icon den "Burp"-Proxy aktivieren.
  7. In Burp Suite sicherstellen, dass "Intercept is on" aktiviert ist.
  8. Beliebige Website aufrufen — der Browser "hängt", da der Request in Burp abgefangen wurde.
Achtung

Solange Intercept eingeschaltet ist, wird der Browser bei jedem Request blockiert, bis in Burp auf Forward oder Drop geklickt wird. Nach dem Testen Interception wieder ausschalten!

The Burp Suite Browser

Burp Suite bringt einen eingebauten Chromium-Browser mit, der bereits für die Proxy-Nutzung vorkonfiguriert ist. Er kann über den Button "Open Browser" im Proxy-Tab gestartet werden.

Vorteile

  • Keine zusätzliche Browser-Konfiguration nötig
  • FoxyProxy-Einrichtung entfällt
  • Automatisch mit Burp-Proxy verbunden

Problem: Root-User unter Linux

Beim Ausführen als Root-User kann es zum Fehler "Cannot create sandbox" kommen. Zwei Lösungen:

Lösung 1 (Empfohlen)

Einen nicht-root Benutzer erstellen und Burp Suite von diesem Account aus verwenden.

Lösung 2 (Riskant)

Settings → Tools → Burp's browser → "Allow Burp's browser to run without a sandbox" aktivieren.
Sicherheitsrisiko: Ein kompromittierter Browser ohne Sandbox könnte einem Angreifer direkten Systemzugriff ermöglichen.

12

Scoping and Targeting

Bei realen Tests erzeugt der Browser eine Fülle an Traffic (Werbung, Tracking, CDNs), die nichts mit dem Ziel zu tun hat. Über Scoping wird Burp Suite angewiesen, sich auf bestimmte Ziele zu fokussieren.

Scope einrichten

  1. Zum Target-Tab wechseln.
  2. Rechtsklick auf das Ziel in der Site Map → "Add To Scope".
  3. Bestätigen, dass out-of-scope Traffic nicht mehr geloggt werden soll.
  4. Verifizieren unter Scope settings im Target-Tab.

Proxy-Filter konfigurieren

Für noch strengere Filterung: In den Proxy Settings unter "Intercept Client Requests" die Regel "And URL Is in target scope" aktivieren. Damit ignoriert der Proxy sämtlichen out-of-scope Traffic vollständig.

Proxying HTTPS

Beim Zugriff auf HTTPS-Seiten über den Proxy zeigt der Browser einen Zertifikatsfehler, da die PortSwigger CA nicht vertraut wird. Das Burp-CA-Zertifikat muss manuell im Browser importiert werden.

Zertifikat installieren (Firefox)

  1. Mit aktiviertem Proxy http://burp/cert aufrufen — die Datei cacert.der wird heruntergeladen.
  2. Firefox öffnen und about:preferences in die Adressleiste eingeben.
  3. Nach "certificates" suchen → Button "View Certificates" klicken.
  4. Auf "Import" klicken und die heruntergeladene cacert.der auswählen.
  5. Checkbox "Trust this CA to identify websites" aktivieren → OK.
Ergebnis

HTTPS-Traffic kann nun ohne Zertifikatswarnungen durch den Burp-Proxy geleitet werden. Auf der AttackBox ist dies bereits vorkonfiguriert.

14

Example Attack — Reflected XSS

In dieser praktischen Übung wird eine Reflected Cross-Site Scripting (XSS)-Schwachstelle in einem Support-Formular demonstriert. Client-seitige Validierungen werden über den Proxy umgangen.

Was ist Reflected XSS?

Bei Reflected XSS wird bösartiger JavaScript-Code als Teil eines Requests an den Server gesendet und in der Response unbereinigt zurückgegeben. Der Code wird im Browser des Opfers ausgeführt. "Reflected" bedeutet, dass nur der anfragende Benutzer betroffen ist.

Angriffsablauf

1. Ziel identifizieren

Support-Formular unter http://MACHINE_IP/ticket/ aufrufen. Das E-Mail-Feld hat eine clientseitige Validierung, die Sonderzeichen blockiert.

2. Legitime Daten eingeben

Formular mit gültiger E-Mail-Adresse und beliebigem Text im Query-Feld ausfüllen. Absenden — der Request wird vom Proxy abgefangen.

3. Payload injizieren

Im abgefangenen Request das E-Mail-Feld durch den XSS-Payload ersetzen:

<script>alert("Succ3ssful XSS")</script>
4. URL-Encoding anwenden

Payload markieren und mit Ctrl + U URL-kodieren, damit Sonderzeichen korrekt übertragen werden:

%3cscript%3ealert(%22Succ3ssful+XSS%22)%3c%2fscript%3e
5. Request weiterleiten

Auf Forward klicken. Der Server verarbeitet den manipulierten Request und gibt ihn unbereinigt zurück. Im Browser erscheint die Alert-Box — XSS erfolgreich!

Key Takeaway

"Client-side filters are absurdly easy to bypass." — Clientseitige Validierung bietet keine echte Sicherheit. Jegliche Eingabevalidierung muss serverseitig erfolgen. Ein Proxy wie Burp Suite umgeht jede Browser-basierte Prüfung trivial.
